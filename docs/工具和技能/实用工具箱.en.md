# TOOL-112: A Practical Toolbox

## Descriptions

- Offered by: A long-running community tool list (the canonical example is the "practical toolbox" page on csdiy.wiki)
- Prerequisites: None; able to download and install software with a browser
- Programming Languages: None; the list is language agnostic and each tool stands alone
- Difficulty: 🌟
- Class Hour: About 1 hour to browse; take what you need rather than installing everything

This is less a course to finish than a list to keep. Its value is not in reading it but in remembering it when needed. Knowing a tool exists can save you half a day; not knowing means writing a worse version yourself.

The list has roughly five groups. **Downloading** centers on academic and e-book resources: Sci-Hub, Library Genesis, Z-Library, and PDF Drive cover papers and books, while qBittorrent and uTorrent handle torrented downloads and seeding. **Design** produces diagrams and architecture charts: excalidraw's hand-drawn style suits figures in reports and slides, tldraw and draw.io fit flowcharts and architecture, and PlantUML generates UML from code so edits do not mean dragging boxes again. **Programming-related** includes the most memorable debugging tools: godbolt compiles your C/C++ code straight to assembly so you can see what the compiler generated, explainshell breaks a shell command into explained segments, regex101 and cyrilex debug and visualize regular expressions, and visualgo together with Data Structure Visualizations draws algorithms as they run. **Learning and reference** covers course sites and documentation, where os-wiki, C++ Reference, OI Wiki, and Arch Wiki are all faster to consult than to search for. **Community and misc** includes Stack Overflow and Stack Exchange as the main venues for asking, HelloGitHub for periodically scanning new projects, and keybr for touch typing.

Some experience in using a list like this: first, remember names and install later. The longer the list, the more it becomes dust in a bookmark folder, and knowing where to look for a category beats installing everything. Second, pick one tool per category and get fluent. You do not need three drawing tools or every command line editor; depth in one beats shallow tries at all. Third, mind licensing and compliance: check whether a tool is free, needs a particular runtime, and whether the resources it fetches are legitimate.

The first pitfall is treating the list as a course to grind through. Installing all of it and running each demo looks diligent but leaves you using none of it in practice. Instead, return to the list when a real need appears, and one use will make it stick. The second pitfall is believing the "killer tool" narrative. Many community recommendations carry strong personal preference, whether for an editor or a productivity app, yet effectiveness depends heavily on context, and what you actually need decides which tool fits. The third pitfall is ignoring alternatives. The list usually shows the author's familiar pick, but most needs have several mature implementations, and searching for peers sometimes turns up one better suited to your platform.

## Personal Resources

If you only remember a few names with long-term value, I would pick these four: godbolt to see what the compiler does, explainshell to see what a command does, excalidraw to draw ideas out, and OI Wiki plus C++ Reference to look up syntax and algorithms faster than searching. Come back to this list for everything else when a real need shows up.
