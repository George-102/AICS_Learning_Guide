# Vim 与 Emacs

## 为什么学习 Vim或Emacs

Vim 和 Emacs 这两款编辑器有如下好处：

- 让你的整个开发过程手指尽量不需要离开键盘：Vim 的模态编辑和 Emacs 的快捷键体系都把光标移动、文本操作和命令执行围绕键盘完成，避免频繁在方向键和鼠标之间切换，让手指一直处在高效输入的状态。
- 方便的文件切换以及窗口/缓冲区管理可以让你同时开发多份文件，甚至同一个文件的不同位置：Vim 有 buffer、window、tab，Emacs 有 buffer、window、frame，都能把多任务编辑组织得很顺手。
- Vim 的宏操作和 Emacs 的键盘宏、Elisp 脚本都可以批量化处理重复操作，例如多行缩进、批量加双引号、批量重命名等，把机械劳动交给编辑器。
- Vim 是很多服务器自带的命令行编辑器，当你通过 `ssh` 连接远程服务器之后，由于没有图形界面，往往可以直接用 Vim 进行开发；Emacs 也能在终端中运行，并可借助 TRAMP 等方式远程编辑，同样适合无图形界面的环境。
- 异常丰富的插件/扩展生态，让你拥有世界上最花里胡哨的终端编辑器组合：Vim 有海量插件，Emacs 有庞大的 Elisp 包生态，两者都能被改造成高度贴合个人工作流的开发环境。
- 可深度定制：Vim 可以通过 `vimrc`、Vimscript、Lua 等配置，Emacs 可以通过 `init.el` 和 Elisp 配置，二者都能把编辑器打磨成个人专属工具。

## 如何学习

不幸的是 Vim(或Emacs) 的学习曲线确实相当陡峭，我花了好几个星期才慢慢适应了用 Vim 进行开发的过程。最开始你会觉得非常不适应，但一旦熬过了初始阶段，相信我，你会爱上它们。

Vim 和 Emacs 是两个年纪比大多数读者还大的编辑器。Vim 的前身 vi 诞生于 1976 年的伯克利，Emacs 的雏形在 MIT 的 AI 实验室出现得更早，Richard Stallman 后来把它整理成 GNU Emacs。它们活到今天并不是靠怀旧，而是因为它们在一个几乎所有编辑器都放弃的方向上坚持的足够久：把编辑这件事拆成最小的、可以用键盘组合的原子操作，然后允许用户自己组装。

Vim 的答案是把编辑分成“模式”。在普通模式里，按键不是用来输入字符，而是动作：`d` 是删除操作符，`w` 是文本对象“下一个词”，合起来 `dw` 就是删一个词，`ci"` 是“改变引号里的内容”。这套组合语法的好处是可以无限派生，一旦熟悉，编辑就从逐字移动变成对结构的一次性操作。代价是学习曲线陡峭，前两周的效率会明显下降。

Emacs 的答案不是模式，而是一个可编程的运行环境。它本质上是一台 Lisp 解释器，编辑器只是它的第一个应用，所以按键绑定的枚举、缓冲区（buffer）、窗口（window）乃至邮件、日程、终端都统一在这一套抽象下。这种“编辑器即操作系统”的路线让 Emacs 的可定制性几乎没有上限，org-mode 就是在这个文化里长出来的：一个纯文本的标记格式，却能承担笔记、待办、日程、表格运算和代码块执行。

两者都不是轻松的选择。本篇的价值不在于说服你换编辑器，而在于提供一个有顺序的学习路径，让你能在真实项目里边用边学，而不是卡在配置阶段。学习时最重要的一条原则是：**先会用，再会配**。Vim 的多数插件只是对自带功能的封装，Emacs 的多数发行版（如 Doom、Spacemacs、Centaur）把别人的配置打包给你，直接套用会让你在出问题时完全无从下手。

## 课程资源

- Vim 课程（中文）：<https://wsdjeg.net/vim-galore-zh-cn/>
- Vim 课程（英文）：<https://learnvimscriptthehardway.stevelosh.com/>
- Emacs 课程（中文）：知乎专栏 <https://www.zhihu.com/column/c_1440829147212279808>
- Vim 练习：Vim 自带的交互教程 `vimtutor`（中文环境会加载中文译本）是第一步就应完成的内容，它把模式切换、删除、粘贴、移动、搜索、替换与文件操作做成十几节动手练习，练到能顺畅操作再往下读。
- Emacs 练习：Emacs 自带的 `C-h t` 交互教程（`help-with-tutorial`），覆盖光标的移动、剪贴板、窗口、搜索与文件操作，并提示 `C-h` 前缀的意义。它是 Emacs 的 `vimtutor` 对应物。
