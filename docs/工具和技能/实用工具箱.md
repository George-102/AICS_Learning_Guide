# TOOL-112：实用工具箱

## 课程简介

- 来源：社区长期收集整理的工具清单（典型案例见 csdiy.wiki 的"实用工具箱"页面）
- 先修要求：无，会用浏览器下载安装软件即可
- 编程语言：无，清单本身与语言无关，被推荐的工具各自独立
- 课程难度：🌟
- 预计学时：浏览约 1 小时，按需取用，不必全装

这不是一门需要按部就班学完的课，而是一份清单。它的价值不在“读”，而在“用时能想起来”。很多工具知道它的存在，就能省下一半的时间；不知道，就只能自己造一个效果更差的。

清单大致分五类。**下载类**以学术与电子书资源为主，Sci-Hub、Library Genesis、Z-Library、PDF Drive 覆盖论文与电子书，qBittorrent 与 uTorrent 处理种子的下载与做种。**设计类**用于产出示意图与架构图，excalidraw 的手绘风格特别适合课程报告与 PPT 里的示意图，tldraw 与 draw.io 更适合画流程与架构，PlantUML 则能用代码快速生成 UML，改动时不必重新拖拽。**编程相关**里最值得记住的是几个调试型工具：godbolt 能把你写的 C/C++ 代码直接编译成汇编，用于观察编译器到底生成了什么；explainshell 能把一段 shell 命令逐段解释；regex101 与 cyrilex 用于调试与可视化正则表达式，visualgo 与 Data Structure Visualizations 则把算法过程画出来。**学习与百科类**包含大量课程与文档站点，os-wiki、C++ Reference、OI Wiki、Arch Wiki 都属于查起来比搜索更快的那一类。**交流与杂项**里，Stack Overflow 与 Stack Exchange 是提问的主战场，HelloGitHub 适合定期扫一遍新项目，keybr 则是练盲打的地方。

使用这份清单有几条经验。第一，先记名字，用时再装。清单越长，越容易变成收藏夹里的灰尘，知道“这类工具上哪找”比全都装一遍有用。第二，同类工具选一个用熟。绘图工具不必同时装三款，文本编辑器脚本不必全都试一遍，熟悉一款的效率远高于每款都浅尝。第三，注意授权与合规。工具本身是否免费、是否要求特定运行环境、下载资源是否合法，都应该在使用前确认。

自学的第一个坑是把清单当课程刷。挨个装一遍、跑一遍示例，看起来很勤奋，实际一项都不会用在真实场景里。正确的做法是遇到具体需求时再回来取用，用一次就记住了。第二个坑是迷信“神器”叙事。社区里很多推荐带有强烈的个人偏好，比如某款编辑器或某个效率工具的拥趸，但工具的有效性高度依赖使用场景，你真正要做的事决定了哪个工具合适。第三个坑是忽略替代方案。清单里列出的往往是作者熟悉的那一款，实际上大多数需求都有多个成熟实现，主动搜索同类替代品，有时能找到更适合自己平台的版本。

## 资源汇总

如果只想记住几个最有长期价值的名字，我会选这四个：godbolt（看清编译器做了什么）、explainshell（看清命令在做什么）、excalidraw（把想法画出来）、OI Wiki 与 C++ Reference（查语法与算法比搜索更快）。其余工具等真正遇到需求时再来翻这份清单。
