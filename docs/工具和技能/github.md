# TOOL-110：GitHub

## 课程简介

- 来源：GitHub 官方文档与开源社区实践整理（[GitHub 官网](https://github.com/)）
- 先修要求：先掌握 Git 的基本操作（提交、分支、远程同步），否则只能在网页上点来点去
- 编程语言：无，平台本身与语言无关，你托管的项目可以是任何语言
- 课程难度：🌟
- 预计学时：基本使用与协作流程 6 小时，形成自己的开源工作方式需长期实践

从功能上说，GitHub 是一个在线代码托管平台：把本地 Git 仓库推上去，多人就能同时开发与浏览。但它的意义早就超出这个定位了，如今它更像一个活跃的开源社区，全世界的开发者在这里分享从工业级深度学习框架到几十行小脚本的各种东西。有人在这里发硬核的技术长文，有人做保姆级入门教程，甚至不少技术书籍本身就开源在仓库里——你现在读的这份指南也是其中之一。

平台的核心使用场景有三层。最基础是托管与备份，一条 `git push` 就把代码放到云端，换机器时 `clone` 回来即可。第二层是协作，用分支与 Pull Request 组织多人改动，把评审过程留在对话里，用 Issue 追踪问题与讨论。第三层是发布与集成，用 Releases 分发版本，用 Actions 做持续集成，让测试和构建在每次提交时自动跑起来。把这三层都用起来，仓库才算真正“活”了。

它真正有价值的地方在于公开与可检索。你遇到的问题，多半已经有人在 issue 里讨论过；你想找的工具，多半已经有人做成了仓库。学会用搜索快速定位这些信息，比从零写代码要高效得多。相应地，当你自己做出有用的东西时，把它公开出去，也可能成为别人的答案。

自学的第一个坑是把 GitHub 当成网盘。仓库不是随便堆文件的地方，没有 README、没有提交历史、没有清晰的目录结构，别人打不开也看不懂。第二个坑是直接在主干上改。个人小项目或许无所谓，但只要涉及协作，就应该习惯开分支、提 PR、走评审，这既是礼貌也是工程能力。第三个坑是忽视开源协议。开源社区不是法外之地，很多项目不允许随意复制分发甚至售卖，使用他人代码前先看清 LICENSE，这既是法律要求，也是社区成员的基本责任。

## 资源汇总

如果还没建立过远程仓库、也没克隆过别人的代码，从官方教程入手最省心。想持续发现有趣的项目，可以关注 HelloGitHub，它定期收录近期流行或有意思的开源项目，配上同名公众号推送，正好解决“不知道去哪找好东西”的问题。

至于如何成为被 star 认可的作者，道理其实很朴素：把你开发中一闪而过的想法写成代码，大方地放到 GitHub 上。开源之所以能成事，靠的是“我为人人，人人为我”的分享精神，而不是技巧。
