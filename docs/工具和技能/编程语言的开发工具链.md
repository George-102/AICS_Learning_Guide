# 编程语言的开发工具链

## 简介

尽管如今的IDE已经有很强大的功能，能够一键打包运行代码，但是某些情况下（例如了解代码构建原理，或是追求极致的构建效率）我们仍然需要使用编程语言的开发工具链。

不同语言工具链的差异，核心在几个方面：**编译/解释方式、构建系统、包管理、测试/格式化/lint、调试与部署、工具链统一程度**。

简单对比：

| 语言                  | 典型工具链                                                   | 特点                                                 |
| --------------------- | ------------------------------------------------------------ | ---------------------------------------------------- |
| C/C++                 | gcc/clang/MSVC + Make/CMake/Bazel + vcpkg/Conan              | 编译型，构建和依赖管理较碎片化，跨平台配置复杂       |
| Java                  | javac + Maven/Gradle + JUnit + JVM                           | 编译到字节码，JVM 统一运行，IDE 和构建生态成熟       |
| C#/.NET               | `dotnet` CLI + MSBuild + NuGet + Roslyn                      | 官方工具链统一，构建、测试、包管理一体化程度高       |
| Python                | CPython/PyPy + pip/venv/poetry/conda + pytest/ruff           | 解释型，虚拟环境和打包工具多，部署常需处理依赖隔离   |
| JavaScript/TypeScript | Node + npm/pnpm/yarn + tsc/Vite/webpack + ESLint/Prettier + Jest/Vitest | 前端工具链最复杂，构建、打包、转译、lint 组合多      |
| Go                    | `go build/test/fmt/mod`                                      | 官方工具链高度统一，依赖和构建简单，常编译成单二进制 |
| Rust                  | `rustup` + `cargo` + crates.io + clippy/rustfmt              | Cargo 统一构建、测试、文档、依赖管理，体验接近 Go    |
| Ruby/PHP              | RubyGems/Bundler、Composer                                   | 解释型，框架生态强，包管理和部署依赖框架约定         |

大家第一次写 hello world 程序的时候一定都记得，在编辑完 `helloworld.c` 之后，需要用 `gcc` 编译生成可执行文件，然后再执行（如果你不理解前面这段话，请先自行谷歌 *gcc 编译* 并理解相关内容）。但如果你的项目由成百上千个 C 源文件组成，并且星罗棋布在各个子目录下，你该如何将它们编译链接到一起呢？假如你的项目编译一次需要半个小时（大型项目相当常见），而你只修改了一个分号，是不是还需要再等半个小时呢？

这时候 GNU Make 就闪亮登场了，它能让你在一个脚本里（即所谓的 `Makefile`）定义整个编译流程以及各个目标文件与源文件之间的依赖关系，并且只重新编译你的修改会影响到的部分，从而降低编译的时间。

CMake 是类似于 GNU make 的跨平台自动软件构建工具，使用 CMakeLists.txt 定义构建规则，相比于 make 它提供了更多的功能，在各种软件构建上广泛使用。强烈建议学习使用 GNU Make 和熟悉 `Makefile` 后再学习 CMake。
